## 📖 معرفی

**EZxray** یک اسکریپت فوق‌پیشرفته و کاملاً خودکار برای راه‌اندازی سرور **Xray** است. نسخهٔ جدید (**Stealth Edition v2**) علاوه بر ۱۲ پروتکل، یک لایهٔ استتار قدرتمند مبتنی بر **VLESS-REALITY-Vision** اضافه می‌کند که در برابر بازرسی عمیق بسته (DPI) و فیلترینگ مقاوم است و **به دامنه یا گواهی SSL نیاز ندارد**.

### 🎯 کاربرد اصلی
- راه‌اندازی سریع سرور حرفه‌ای عبور از فیلترینگ
- استتار ترافیک به‌شکل HTTPS واقعی (مقاوم در برابر DPI و active probing)
- تولید کانفیگ‌های متعدد به‌صورت همزمان
- پشتیبانی از همه دستگاه‌ها (ویندوز، اندروید، iOS، مک، لینوکس)

---

## 🥷 چرا این نسخه «ناشناس‌تر» است؟

نسخهٔ قبلی همهٔ پروتکل‌ها را با `security: none` (بدون رمزنگاری transport) اجرا می‌کرد که با DPI به‌راحتی شناسایی و مسدود می‌شد. در نسخهٔ Stealth:

| ویژگی | توضیح |
|-------|--------|
| **VLESS + REALITY + Vision** | دست‌دادن TLS را از یک سایت واقعی «قرض» می‌گیرد؛ از بیرون دقیقاً شبیه HTTPS عادی دیده می‌شود |
| **بدون دامنه/گواهی** | فقط با IP کار می‌کند؛ نیازی به ثبت دامنه و صدور گواهی نیست |
| **مقاوم در برابر active probing** | اگر کسی پورت را پروب کند، پاسخِ همان سایت واقعی را می‌بیند |
| **روی پورت 443** | ترافیک کاملاً شبیه مرور وبِ معمولی است |

### 🔎 انتخاب خودکار بهترین دامنه (SNI)
دامنه‌های پرکاربرد مثل microsoft/google/apple ممکن است برای مسیر شما دستکاری یا مسدود شده باشند. به همین دلیل اسکریپت **به‌صورت زنده از روی خودِ سرور** مجموعه‌ای از دامنه‌های کاندید را تست می‌کند و فقط آن‌هایی را انتخاب می‌کند که:
- روی پورت 443 در دسترس باشند
- **TLS 1.3** را مذاکره کنند
- از گروه کلید **X25519** استفاده کنند (شرط لازم REALITY)
- ترجیحاً از **HTTP/2 (ALPN h2)** پشتیبانی کنند

دامنه‌های کاندید شامل: `www.microsoft.com`, `www.cloudflare.com`, `www.apple.com`, `dl.google.com`, `www.bing.com`, `aws.amazon.com`, `cdn.jsdelivr.net`, `www.samsung.com`, `www.icloud.com`, `swcdn.apple.com`, `www.tesla.com` و … . اگر هیچ‌کدام در دسترس نباشد، به‌صورت امن به یک مقدار پیش‌فرض برمی‌گردد.

## 🛠️ بهبودها و رفع باگ‌ها در این نسخه

- ساخت پوشهٔ `/var/log/xray` پیش از اجرا (در غیر این صورت Xray بالا نمی‌آمد)
- حذف `flow: xtls-rprx-vision` نامعتبر از inboundهای VLESS روی WebSocket
- تعریف تابع گمشدهٔ `copy_to_clipboard`
- حذف بلوک/قانون routing معلق `api` که هیچ inbound نظیری نداشت
- جایگزینی تشخیص پورت مبتنی بر `nc` با `ss`/`netstat` (بدون وابستگی به netcat)
- پسوردهای URL-safe برای Trojan/SS و توکن مسیر اختصاصی WebSocket
- افزودن **سرویس systemd** (راه‌اندازی مجدد خودکار، مقاوم در برابر ریبوت)
- **بکاپ واقعی** کانفیگ در `/root/xray-backups/`
- **اعتبارسنجی کانفیگ** با `xray run -test` پیش از راه‌اندازی
- تولید خودکار کلید **x25519** و **shortId** برای REALITY

## ⚡ پرفورمنس اتصال (BBR + تیونینگ TCP)

برای اینکه کیفیت اتصال کاربر **عالی** باشد، اسکریپت به‌صورت خودکار تنظیمات شبکه را در سطح سیستم بهینه می‌کند (روی `/etc/sysctl.d/99-xray-performance.conf`):

- **BBR** گوگل + صف‌بندی **fq** (تأخیر کمتر، سرعت بیشتر، مخصوصاً روی شبکه‌های پرتلفات)
- **TCP Fast Open** برای برقراری سریع‌تر اتصال
- بافرهای سوکت بزرگ‌تر برای throughput بالا
- تنظیمات بهینهٔ backlog، keepalive و بازهٔ پورت‌ها

این تنظیمات برای **همهٔ پروتکل‌ها** اعمال می‌شود، نه فقط یکی. بررسی فعال بودن BBR:
```bash
sysctl net.ipv4.tcp_congestion_control   # باید bbr باشد
```

## 🚀 نصب

### حالت تک‌سروره (فقط سرور خارجی)
روی **سرور خارجی** اجرا کن:
```bash
bash EZxray.sh
```
کلاینت‌ها مستقیماً به IP سرور خارجی وصل می‌شوند.

### حالت دو‌سروره (Relay / تونل) — حرفه‌ای و سریع‌تر برای ایران

```
کاربر ──►  سرور داخلی (Relay)  ══►  سرور خارجی (EZxray)  ──►  اینترنت
          IP داخلی، پینگ پایین      لینک دیتاسنتری سریع
```

۱) روی **سرور خارجی**، `EZxray.sh` را نصب کن (مثل بالا).
۲) روی **سرور داخلی**، اسکریپت رله را اجرا کن:
```bash
bash EZtunnel.sh                 # تعاملی: IP سرور خارجی را می‌پرسد
# یا مستقیم:
bash EZtunnel.sh <IP-سرور-خارجی>
```

`EZtunnel.sh` با استفاده از **dokodemo-door** هر پورت را به سرور خارجی فوروارد می‌کند، **BBR** را فعال می‌کند و سرویس systemd می‌سازد.

**مهم:** در لینک‌های اشتراک، فقط **آدرس (IP)** را از سرور خارجی به **IP سرور داخلی** تغییر بده. پورت، UUID، SNI، `pbk` و `sid` **بدون تغییر** می‌مانند (چون REALITY/TLS روی سرور خارجی پایان می‌یابد).

```
قبل:  vless://UUID@IP-خارجی:443?...sni=...&pbk=...&sid=...
بعد:  vless://UUID@IP-داخلی:443?...sni=...&pbk=...&sid=...
```

**چرا بهتر است؟** کاربر به یک IP داخلی با تأخیر کم وصل می‌شود و پرش بین‌المللی به‌صورت سرور‌به‌سرور (کیفیت دیتاسنتر) انجام می‌گیرد؛ نتیجه سرعت و پایداری به‌مراتب بهتر.
