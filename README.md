## 📖 معرفی

**EZxray** مجموعه‌ای از اسکریپت‌های Bash برای راه‌اندازی سریع و حرفه‌ای سرور **Xray** است:

| فایل | اجرا روی | کار |
|------|----------|-----|
| **`EZxray.sh`** | سرور خارجی (Exit) | نصب کامل Xray با ۱۲ پروتکل + لایهٔ استتار REALITY |
| **`EZtunnel.sh`** | سرور داخلی (Relay) | تونل/رله به سرور خارجی برای سرعت و پایداری بیشتر در ایران |

نسخهٔ Stealth علاوه بر ۱۲ پروتکل، لایهٔ **VLESS-REALITY-Vision** را اضافه می‌کند که در برابر **DPI** و **active probing** مقاوم است و **به دامنه یا گواهی SSL نیاز ندارد**.

---

## ✨ قابلیت‌ها

- 🥷 **VLESS-REALITY-Vision** — استتار ترافیک به‌شکل HTTPS واقعی (بدون دامنه/گواهی)
- 🔎 **انتخاب خودکار بهترین SNI** — تست زندهٔ دامنه‌ها از روی خودِ سرور (TLS1.3 + X25519)
- ⚡ **BBR + TCP FastOpen** — بهینه‌سازی سطح سیستم برای بهترین کیفیت اتصال
- 🔗 **لینک Subscription + QR Code** — وارد کردن همهٔ کانفیگ‌ها با یک URL یا اسکن
- 🌉 **معماری دو‌سروره (Relay)** — سرور داخلی + خارجی برای سرعت بالا در ایران
- 🛡️ **سرویس systemd** — راه‌اندازی مجدد خودکار، مقاوم در برابر ریبوت
- 💾 **بکاپ خودکار** + اعتبارسنجی کانفیگ پیش از اجرا

---

## 📡 پروتکل‌های فعال (روی سرور خارجی)

### لایهٔ استتار (توصیه‌شده — Anti-DPI)
| شماره | پروتکل | توضیح |
|------|--------|--------|
| ۱–۳ | **VLESS-REALITY-Vision** | استتار کامل، SNI خودکار، روی پورت 443 و دو پورت دیگر |

### لایهٔ fallback (WebSocket)
| شماره | پروتکل |
|------|--------|
| ۴–۶ | VMESS / Trojan / Shadowsocks |
| ۷–۹ | VMESS 2 / Trojan 2 / Shadowsocks 2 |
| ۱۰–۱۲ | VMESS 3 / Trojan 3 / Shadowsocks 3 |

> برای حداکثر مقاومت در برابر فیلترینگ، از کانفیگ‌های **۱ تا ۳ (REALITY)** استفاده کنید.

## ⚙️ پیش‌نیازها

- سرور لینوکس **Ubuntu/Debian** با دسترسی **root**
- دسترسی به اینترنت (برای نصب Xray و تست زندهٔ دامنه‌ها)
- برای حالت دو‌سروره: یک سرور **خارجی** + یک سرور **داخلی**

## 🚀 نصب و راه‌اندازی

### گام ۰ — دریافت فایل‌ها
```bash
git clone https://github.com/ast2019/EZxray_Direct_Server.git
cd EZxray_Direct_Server
chmod +x EZxray.sh EZtunnel.sh
```

---

### 🅰️ حالت تک‌سروره (فقط سرور خارجی)

روی **سرور خارجی** اجرا کن:
```bash
sudo bash EZxray.sh
```

اسکریپت به‌صورت خودکار:
1. ابزارها و **Xray** را نصب می‌کند
2. بهترین دامنه‌های **SNI** را به‌صورت زنده تست و انتخاب می‌کند
3. کلیدها/UUIDها و کلید **REALITY (x25519)** را می‌سازد
4. کانفیگ ۱۲ پروتکل را ساخته و **اعتبارسنجی** می‌کند
5. سرویس **systemd**، فایروال و **BBR** را فعال می‌کند
6. **لینک Subscription**، **QR** و فایل خروجی را تولید می‌کند

در پایان، کانفیگ‌ها و لینک Subscription نمایش داده می‌شوند. کلاینت‌ها مستقیماً به **IP سرور خارجی** وصل می‌شوند.

---

### 🅱️ حالت دو‌سروره (Relay / تونل) — حرفه‌ای و سریع‌تر برای ایران

```
کاربر ──►  سرور داخلی (EZtunnel.sh)  ══►  سرور خارجی (EZxray.sh)  ──►  اینترنت
          IP داخلی، پینگ پایین             لینک سرور‌به‌سرور سریع
```

**۱) روی سرور خارجی** → نصب کامل:
```bash
sudo bash EZxray.sh
```

**۲) روی سرور داخلی** → رله را اجرا کن:
```bash
sudo bash EZtunnel.sh                 # تعاملی: IP سرور خارجی را می‌پرسد
# یا مستقیم با آرگومان:
sudo bash EZtunnel.sh <IP-سرور-خارجی>
```
`EZtunnel.sh` با **dokodemo-door** هر پورت را به سرور خارجی فوروارد می‌کند، **BBR** را فعال می‌کند و سرویس systemd می‌سازد.

**۳) ویرایش لینک کلاینت** — فقط **آدرس (IP)** را از سرور خارجی به **IP سرور داخلی** تغییر بده. پورت، UUID، SNI، `pbk` و `sid` **بدون تغییر** می‌مانند (چون REALITY/TLS روی سرور خارجی پایان می‌یابد):
```
قبل:  vless://UUID@IP-خارجی:443?...sni=...&pbk=...&sid=...
بعد:  vless://UUID@IP-داخلی:443?...sni=...&pbk=...&sid=...
```

**چرا بهتر است؟** کاربر به یک IP داخلی با تأخیر کم وصل می‌شود و پرش بین‌المللی به‌صورت سرور‌به‌سرور (کیفیت دیتاسنتر) انجام می‌گیرد؛ نتیجه سرعت و پایداری به‌مراتب بهتر.

- **اندروید:** v2rayNG، NekoBox

- **ویندوز:** v2rayN، NekoRay

## 🔗 Subscription + QR

- **لینک Subscription:** `http://<IP>:<SUB_PORT>/<توکن تصادفی>.txt` (سرویس systemd به نام `xray-sub`؛ توکن تصادفی نقش رمز را دارد)
- **QR همهٔ کانفیگ‌ها:** به‌صورت PNG در `/root/xray-qr/`
- **QR لینک Subscription:** هنگام اجرا مستقیماً در ترمینال نمایش داده می‌شود

---

## ⚡ پرفورمنس (BBR)

تنظیمات شبکه به‌صورت خودکار در `/etc/sysctl.d/99-xray-performance.conf` اعمال می‌شود (BBR + fq + TCP FastOpen + بافرهای بزرگ). بررسی فعال بودن:
```bash
sysctl net.ipv4.tcp_congestion_control   # باید bbr باشد
```

## 🛠️ مدیریت سرویس

```bash
# سرور خارجی (و رله)
systemctl status xray        # وضعیت
systemctl restart xray       # ریستارت
systemctl stop xray          # توقف
journalctl -u xray -f        # لاگ زنده
ss -tulpn | grep xray        # بررسی پورت‌ها

# سرور Subscription (فقط سرور خارجی)
systemctl status xray-sub
```

### مسیر فایل‌های خروجی (سرور خارجی)
- کانفیگ‌ها: `/root/xray-configs-stealth.txt`
- Subscription (base64): `/root/xray-subscription-base64.txt`
- QRها: `/root/xray-qr/`
- بکاپ: `/root/xray-backups/`

## 🐞 رفع اشکال (Troubleshooting)

| مشکل | بررسی |
|------|--------|
| Xray بالا نمی‌آید | `journalctl -u xray -n 50` |
| کانفیگ نامعتبر | اسکریپت پیش از اجرا با `xray run -test` چک می‌کند؛ خطا را نمایش می‌دهد |
| BBR فعال نشد | روی بعضی VPSها (OpenVZ/LXC) ممکن نیست؛ یک‌بار ریبوت کن |
| اتصال REALITY برقرار نمی‌شود | مطمئن شو SNI انتخابی از سرور در دسترس است و پورت در فایروال ابری باز است |
| رله وصل نمی‌شود | روی سرور داخلی: `nc -z <IP-خارجی> 443` و `journalctl -u xray -f` |

## 🔒 نکات امنیتی

- پروتکل‌های fallback (VMESS/Trojan/SS) با `security: none` هستند؛ برای استتار از کانفیگ‌های **REALITY (۱–۳)** استفاده کن.
- برای چرخش هویت (کلید/UUID جدید)، اسکریپت را دوباره اجرا کن.
- لینک Subscription را فقط در اختیار افراد مورد اعتماد قرار بده (هرکس URL را داشته باشد به همهٔ کانفیگ‌ها دسترسی دارد).
